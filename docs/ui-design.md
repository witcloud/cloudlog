# CloudLog UI 设计规范

> **消费方**：实现前端的 AI Agent。本文是可直接执行的硬约束，不是灵感板。
> **真源边界**：接口契约（路径、字段、参数名）以后端 SpringDoc 与代码为准；业务语义、状态、权限模型以 [business-model.md](./business-model.md) 为准，本文**不复述**、不覆盖。本文只规定「页面长什么样、怎么反应」。
> **Token 边界**：Token 实体（名称与值）唯一来源是 `cloudlog_web/src/assets/styles/variables.css`。本文规定 Token 的**语义归属与使用规则**，不复制色值、字号、间距的具体数值——需要数值时读 `variables.css`，不要在组件里另起一份。
> **口径**：「必须 / 禁止」= 违反即返工；「默认」= 无正当理由不得偏离；「可选」= Agent 自行判断。
> **范围纪律**：本文只覆盖 business-model.md 中明确存在的页面与交互。业务里没有的界面（首页 Hero、归档页、推荐位、分享面板、阅读量图表、消息中心、多语切换……）本文一律不规定，实现时也**不得添加**。

## 1. 设计原则

| # | 原则 | 约束含义 |
|---|---|---|
| P1 | **阅读优先** | 站点主体是长文。行宽、行高、字号、对比度、留白都为正文服务；任何装饰元素与正文争空间时，删装饰。 |
| P2 | **单一强调** | 全站只有**一枚**强调色（朱砂）。它在单个视口内的面积占比 ≤5%。第二枚强调色、渐变、彩色块面均属违规。 |
| P3 | **最少字段** | 表单只放业务必需的输入项。不预留「以后可能用到」的字段、开关、筛选器。 |
| P4 | **发丝线分层** | 层级靠底色微差 + 1px 发丝线表达，不靠阴影堆叠。全站只允许一枚极轻阴影。 |
| P5 | **静止默认** | 页面默认不动。动效是反馈手段，不是氛围手段；无反馈目的的动画一律删除。 |
| P6 | **响应式同构** | 同一信息在窄屏与宽屏都必须存在，只改**位置与密度**，不删内容、不做两套 DOM 互相隐藏。例外：首页的站点统计与热门列表只在宽屏右栏（2026-10-02 裁决，见 §3.1）；文章页悬浮操作栏在窄屏收掉「返回 / 作者簇 / 查看评论」三格、只留点赞与分享（同日裁决，见 §3.2）。 |
| P7 | **明暗同体系** | 暗黑模式是同一色相体系的明度反转，不是另一套配色。禁止为暗色单写组件样式。 |
| P8 | **不发明数据** | 界面上的数字、时间、状态只来自接口返回。取不到就留空或显示 `—`，禁止占位估算、假 0、装饰性统计。 |
| P9 | **失败必须出声** | 任何请求失败都要让用户看见原因；成功反馈按 §5.1 收敛。 |

## 2. 整体布局

### 2.1 前台（站点框架）

- **顶栏是单一横向条**，自左向右：汉堡入口（仅窄屏）→ wordmark（站标，点击回首页）→ 主导航 → ｜ 右半区起：搜索框 → 主题切换 → 「创作」下拉（写文章 / 我的草稿）→ 账号簇（内含「管理后台」入口）。「创作」下拉与「管理后台」均仅博主可见。顶栏高度取 `--header-h`。窄屏（`≤37.5rem`，§6.4）由**账号簇让位**给搜索框，左半区不缩——剩余宽度被站标与汉堡占满，再挤就要裁站标。
- **内容容器**最大宽度取 `--container-max`，居中，左右留白随视口收缩；页脚为内联单行，挂在内容索引页右栏末端（窄屏无右栏时回落单栏底部）。

- **账号簇按状态渲染**：未登录 = 「登录」纯文本 + 「注册」描边按钮；已登录 = 头像 + 下拉（个人资料 / 设置 / 管理后台（仅博主）/ 退出）。「写文章」与「我的草稿」由「创作」下拉承载，不放进账号下拉。
- **写作类入口（写文章、发布、后台）只对博主可见**；普通登录用户与匿名访客看不到这些入口。权限判定依据见 business-model.md B1.2，UI 只做**呈现层**收敛，不作为安全边界。
- **主导航项固定为「首页 · 关于」**，不增加栏目。分类与标签是**内容索引的筛选维度**，不是顶栏导航项。搜索是全站唯一的一个框，**就长在顶栏右半区**（`type="search"` 内联输入框：常态 `min(11rem,34vw)`、`:focus` 拉到 `min(20rem,46vw)` 并把描边转到 `--color-rule-strong`，宽度用 `--dur-short` 过渡），提交只靠回车——框左那枚放大镜是**装饰**（`pointer-events: none`），不可点；输入后右侧出现一枚清空 ×。这不属于主导航，也不做成「点图标再展开一层输入框」——桌面端那样等于把一次动作拆成两次。窄屏抽屉里的「搜索」链接只是跳到 `/search`，不是第二个框。
- **窄屏把顶栏收为汉堡抽屉**，抽屉内允许按组增加链接，组用一行小标签分隔：导航（首页 / 关于 / 搜索）、写作（发布文章 / 我的草稿）、账号（个人资料 / 设置 / 后台入口 / 退出，未登录时为登录 / 注册）。窄屏不新增宽屏没有的功能。
- **内容索引型页面用三栏网格**：筛选栏 ｜ 主列表 ｜ 统计与热门（见 §3.1）。
- **文章页用两栏**：阅读列 ｜ 侧栏（目录 + 作者）。宽视口下额外允许一列**悬浮操作栏**（见 §3.2）。
- **功能型页面（关于 / 登录 / 注册 / 账号设置）沿用同一顶栏与容器**，只按用途收窄中心区。
- **例外：编辑器页不带站点外框**（无站点顶栏、无页脚），是全屏工作台；它留在布局树内以保住列表页缓存，只跳过外框渲染。

### 2.2 后台（独立框架）

- **框架是左侧导航 + 主工作区**，不入前台站点框架。主工作区自上而下：页头（标题 + 该页主操作按钮）→ 工具条（筛选 / 搜索）→ 主体（数据表格或表单）→ 分页。
- **左侧导航分三组八项**，与 business-model.md §4.6 的管理能力一一对应，不增不减：
  - 工作台（Dashboard，无组名，独占首档）
  - 内容管理：文章 · 评论 · 分类 · 标签（**分类与标签是两个独立页面，不合并**）
  - 系统管理：用户 · 系统设置 · **日志管理**（两类日志共用这一个入口——导航按**管理对象**切分，访问日志与登录日志是同一对象下的两个页签，进去再切，见 §3.11）
  - 组名作为一行小标签显示在条目之上；窄屏收为抽屉，组结构不变。每项一枚 `@element-plus/icons-vue` 的功能性小图标（§4.6 允许的例外面）。
- 后台是**任务型密集界面**：以表格为主载体，行高密度高于前台，不套用前台的发丝线留白节奏。
- 后台**只共用 Token，不共用前台版式**：不继承前台页脚与三栏网格，不引第二配色。
- 后台导航当前项必须高亮（朱砂洗染底 + 朱砂文字）；页头提供一条「返回前台站点」出口，不放进导航组里。
- `我的草稿`、`个人资料`、`账号设置` 属于**前台框架下的账号页**（沿用站点顶栏），不在后台导航内，也不改造成后台布局。

## 3. 核心页面说明

### 3.1 首页（内容索引）

- **定位**：`/` 即文章列表，**无 Hero、无轮播、无引言大图**。
- **构成**：三栏（分类筛选 ｜ 滚动加载的文章列表 ｜ 统计卡 + 热门列表 + 页脚）。
- **筛选栏**：全部 / 各分类，选中项用强调色洗染底 + 强调色文字。可清除（「清除筛选」）；无分类数据时整栏收起。
- **排序条**：列表之上两个取值「推荐 / 最新」，**默认是推荐**（URL 不带 `sort`），选最新落 `?sort=latest`——刷新与分享链接都按 URL 还原，两个 tab 不走前端二次排序。两个按钮是**一组筛选控件不是页签**：`role="group"` + `aria-label="文章排序"` + 当前项 `aria-current`，不配 `tabpanel`、不做方向键导航（页签语义要求配套的面板与键盘行为，硬套是假无障碍）。选中项用下划线式强调，靠文字本身承载状态（§5.7）。**这一条自成一块抬升面板**：与下方列表框不留间距、下缘两角收平，描边由列表框上移 1px 与它叠合——两条发丝线并排就是双线，这是 §2.1「发丝线分层」的一处显式让位。窄屏照旧排在列表之上，不换位置。
- **列表行**：发丝线分隔，**不堆卡片**。一行内为标题 + 摘要 + 计数 + 一枚归属字段：首页与搜索页是作者名 + 标签，个人页与作者主页是分类名。**没有日期**（2026-10-05 按实现校准——原先这行写的「分类/标签 + 日期」里，分类与标签从不在同一行并列，日期从未落地）。置顶文章有可见的置顶标记（强调色，属 P2 允许的少量用量）。
- **图片位**：行右侧一枚小尺寸封面缩略图，1px 发丝线边框 + 小圆角；无封面的文章**不留空位、不放占位图**。这是全站唯一图片装饰位。缩略图指 CSS 缩放原图（封面为完整 URL），不生成缩略图文件（business-model.md §6）。
- **统计卡**：只展示接口能返回真值的项（文章总数 / 分类数 / 最近更新）。取不到显示 `—`。
- **热门列表**：数据性排名，前三名序号允许强调色；允许换页操作，换页用透明度淡入。
- **窄屏（<60rem）**：三栏塌为单栏，分类改为列表上方一排横滑按钮（进抬升面板，不带计数，选中项强调色洗染底），滚动超宽边缘渐隐；站点统计与热门列表**只在宽屏右栏**，窄屏不设唤出入口；缩略图尺寸降档。
- **禁止**：骨架卡片堆叠、阅读进度条、标签云、推荐位。

### 3.2 文章详情

- **构成**：文章头（标题 / 日期 / 作者 / 分类 / 计数）→ 正文 → 正文页脚（标签）→ 评论区；右栏 = 目录 + 作者卡。
- **正文排版是本页的硬要求**：侧栏 `15rem` 定宽，容器余量全给阅读列（整组不居中、两侧不留空带，2026-10-05 裁决）；行宽上限由容器定死，**不随视口无限拉伸**，也不再取编辑器的写作面宽度（差量见 §3.9）；标题层级、段距、列表、引用、代码块、表格、图片都必须有明确且互相可辨的样式；正文内链接用强调色。
- **正文插图与灯箱**：阅读面的 `md-preview` **关掉库自带的 medium-zoom**（`:no-img-zoom-in`）——库默认只能放大到原图尺寸、不响应 Esc、也没有滚轮缩放，看图统一走站点自绘的那一层，**两层不许并存**。灯箱（`ImageLightbox`）是全站唯一一枚暗面：`Teleport` 到 body、开时锁住页面滚动（`body.overflow: hidden`，关时与组件卸载都还原）、**控件只有右上角一个关闭钮**（P3 最少字段），缩放由手势承担——滚轮以指针为锚、双击在放大与复位之间切换、放大后能拖拽平移，`Esc` 关闭。被限高的图等比收窄后由 `text-align: center` 兜底居中，完整画面点进灯箱看。键盘必须停得下来：渲染后给正文每张图补 `tabindex` 与一句最低限度的 `alt`（作者写 `![](url)` 时不会想到读屏，落成空 alt 等于这张图对读屏不存在），`Enter` / `Space` 与点击走同一条路；**不改 `role`**（img 换成 button 会把「这是一张图」这层语义整个丢掉）。代码块的行号槽同样关着（`:show-code-row-number="false"`，库默认用 `!important` 撑出 3.5em 左栏位而实测一个行号都不渲染）；高亮两套都是 `one-dark`，不随主题切换（§4.2）。
- **正文页脚**：正文之后一条发丝线（线上两侧各 `--space-md`），标签在左、互动按钮的窄屏面孔在右；无标签时按钮独占该行，发丝线仍在。**标签用可见前缀「标签：」**（2026-10-05 裁决），13px / `--color-ink-3`，与芯片文字顶同一线——标签组须 `align-items: center`，否则前缀作为 flex 项被撑到芯片高、文字顶到顶上。不用 `#` 记号：前缀与 `#` 是同一件事说两遍。**这枚前缀只在本页出现**，列表行的标签保持裸芯片（差量见 §3.3）。
- **目录**：按正文标题生成，当前阅读位置项高亮；窄屏收为可折叠块。
- **作者卡**：右栏上部，承载作者身份、三格统计与一枚关注入口。**整个头带（头像 + 名字 + 那一行职业）是链接，指向 `/authors/{id}` 作者主页**；职业为空就不写那一行，不拿「未知」或站名去顶。三格依次为**文章 / 粉丝 / 阅读**，前两格与第三格的来源不同：文章与阅读是该作者**全部已发布文章**的查询期聚合（不落列，`db-design.md` 的「users 不存可计算值」不破），取自详情响应 author 块的 `articleCount` / `viewCount`；粉丝格直接读 `author.followers`，按 `follows` 实际条数即时统计。这与文章头计数、悬浮操作栏徽标分属**两套口径**——后两者是「本篇」，卡片是「全部」，禁止互相复用字段；`author.likeCount`（全部获赞）在卡片上没有位置，别顺手补第四格（P3）。取不到显示 `—`，不得以 `0` 顶替（P8）。点赞只改本篇计数，卡片按页面快照不随之跳动，重新加载后才是新值。关注按钮是**次级描边按钮**——本页的提交类主按钮是「提交评论」，主按钮一页不多于一个（§6.2）。按钮通栏置于卡片底部，**文案说动作不说状态**：未关注是「关注」，已关注是「取消关注」；已关注态只由洗染底 + 强调色描边区分（状态本身另有文字承载，§5.7）。**按钮不带任何数字**——非零也不并进文案：一个数字就是一个会被当成断言的展示信号，而且卡片是页面快照、点了赞和取了关都不会跟着跳，摆在按钮上只会让人以为它是实时的（要读总量去作者主页页头）。关注状态与关注数以接口返回为唯一来源，禁止乐观更新，提交中按钮 loading 并禁用重复点击（§5.3）。**作者本人不出现该入口**（服务端另有 400 兜底）；未登录点击按 §5.5 引导登录。语义见 business-model.md §4.7。
- **互动条**：仅包含点赞按钮与只读的评论数（与文章头计数同源）；点赞状态与数值以接口返回为唯一来源，禁止乐观更新；点击后按钮进入提交中态，返回后一次性更新；未登录点击的引导按 §5.5 执行。语义见 business-model.md §4.5。
- **悬浮操作栏**：在**多栏成立的视口**就出现（§6.4 的 `60rem`，与右栏同生同灭——汉堡一出来它才换成文末一行）。横向落点与下面那条面板位移读同一个值 `--gutter`（容器内容缘离窗口多远 = `max(--space-lg, (100vw − 72rem)/2)`），分两个模式：**留白够时竖栏整个待在卡外**，右缘距卡片一档 `--space-xl`，面板跟着容器走；**留白被吃掉 96px 之后竖栏钉在离窗 `--space-sm` 处不再右移，同时两张卡的左缘被钉在离窗 96px 处不再往左爬**——收窄的是面板与正文，**竖栏永远留在面板边框之外，两者不重叠**。96px = 离窗 12 + 栏身 `2.75rem` + 栏卡间距 40；那档 `--space-xl` 的栏卡间距两个模式都不变。门槛当天走过 `84→81→84→60rem`：最后一版不再靠提前换面孔躲开留白不足（实测 1600/1400/1344/1200/1100/960 六档，1344 起面板左缘恒定 96px、栏卡间距恒定 40px，文字列 830 → 511）。**不放进球内**（2026-10-05 试过两版：卡缘外 40px 与卡内左内衬 108px，后者让正文列从 840 掉到 754，当天撤回）。承载的动作按顺序是五格：**返回**（纯图标，回列表）、**作者簇**（头像 + 一枚关注药丸；作者卡完全滚出视口后才出现，是卡片的浓缩替身——卡片唯一的动作被一起搬过来，`IntersectionObserver` 的顶部扣除固定顶栏高度，被顶栏遮住即算离开）、**点赞**带只读角标、**评论定位**带只读角标、**分享**。**这一栏里没有回顶钮**：回顶是全站右下角那一枚，挂在站点布局上（§5.6），竖栏那颗头像按钮的语义是「回到文章开头查看作者」，两者不许混为一谈。作者簇这一格只在 `canFollow` 时出关注药丸（本人不出现），药丸**骑在头像下缘**、实底、窄栏宽 2.75rem 放不下「取消关注」四字，所以它的已关注态写状态词**「已关注」**——与卡片按钮的「取消关注」刻意不同（卡片是通栏按钮、说动作；药丸是小面、说状态），也避开 `aria-label` 与可见文字打架。两枚的状态都只由文字与洗染底承载。**分享入口**为微博 / 微信 / 复制链接三项（菜单项就叫这两个字，不写「跳转」「扫码」这类说明词），每项前带一枚对应标（微博与微信为品牌单色标，见 §4.6；复制链接用链形图标），选中即收起气泡；微信用二维码弹层，码由前端本地生成（编码器 `qrcode-generator` 是已声明的运行时依赖、内联 SVG 输出，浅色底恒不反色），**不得外呼第三方服务**（含在线二维码生成接口）。分享气泡的开口方向跟竖栏的面孔一起换：`≥60rem` 竖栏是 `fixed`、气泡从**右侧**出（浮层也得同它一起锚视口，否则「漂一下再复位」）；不足 `60rem` 时**这一整组按钮换成正文末尾的一行**，气泡改从**上方**出（`placement: 'top'`，实测），strategy 跟着从 `fixed` 换回 `absolute`——按钮回到正文流里之后，`absolute` 才与触发点同步（判据见 §6.4）。**窄屏那一行只有两格：点赞与分享**——「返回」是竖栏专属的导航、「作者簇」与页顶的卡片重复、「查看评论」在窄屏没意义（评论区就紧接在正文面板下面，数量在「评论 N」标题上已经写了），这三格在窄屏收掉，是 P6 的例外（2026-10-02 裁决）。**除这五格外不加新按钮。**
- **评论区**：列表按层级两级展示（根评论 + 回复）；评论者取自用户关联信息，`user_id` 为空属防御性情形，展示固定占位「匿名」，不展示任何身份标识；未登录时评论框替换为登录引导；提交反馈以接口返回的最终 `status` 为准（business-model.md §4.4 第 4 条）——`approved` 提示「评论已发布」并重新拉取列表使新评论立即可见，`pending` 提示「审核通过后展示」且**不得承诺已发布**；禁止以「重新拉取后是否多出一条」反推状态。
- **越权与不存在**：非公开内容或已删除文章，展示**单一**的「不存在或无权访问」态，不泄露差异原因（判定依据见 business-model.md A3.1）。
- **编辑入口**：仅博主或作者本人可见，跳编辑器；这是呈现层入口，权限由后端兜底。

### 3.3 分类页 / 标签页

- 与首页**同一套列表语义**，只是筛选条件由 URL 决定；不新做第三种版式。
- 页头一行显示维度名 + 该维度下的真实篇数 + 清除筛选入口，仅在搜索 / 标签筛选时出现；分类筛选的状态由筛选控件本身（大屏左栏选中项 / 小屏顶部横滑条）承载，不显示页头行。
- 空结果：显示「该分类下暂无文章」+ 返回首页链接；**不显示装饰插画**。
- 标签在列表行内并列排布，数量按行宽换行**不截断为省略号**（截断会隐藏可点项）。**分类与标签不在同一行并列**（2026-10-05 校准，见 §3.1 列表行）：首页与搜索页的行只给标签，个人页与作者主页的行只给分类名。
- **列表行的标签不带「标签：」前缀，也不用 `#`**（2026-10-05 裁决：前缀只给详情页 §3.2）。这是有意差量，不是漏改——实测一枚前缀占 44px，带封面且两个标签的那一行在 576px 以下放不下它，标签组会被挤到换行、行高从 22 涨到 52，缩略图与正文列的两缘咬住随之脱开（§3.1 的缩略图位）。

### 3.4 搜索页

- 入口是顶栏搜索图标/输入框；提交后进入独立搜索路由，**不在顶栏内嵌下拉结果**。
- 结构 = 搜索框（保留当前关键词）+ 结果列表（复用 §3.1 列表行）+ 分页。
- 页头显示真实命中条数；零结果显示「无匹配」+ 清空关键词，不保留旧列表。
- 提交方式是**显式提交**（回车或搜索按钮），输入过程中不逐字符发请求；关键词写在 URL query 上，因此可直接分享、回退后关键词仍在。
- 搜索范围见 business-model.md §3.2，参数以接口文档为准，UI 不自造高级筛选器。

### 3.5 登录 / 注册

- 单列窄表单（居中，宽度上限按小号表单档位），沿用站点顶栏。登录与注册是同一个视图的两态（路由 `meta.title` 随态切换），**共用的只有邮箱与口令两格**，其余按态增删，不做两份 DOM。
- **登录**：邮箱 + 密码（口令框带「显示密码」眼睛）→ 底栏两个并列入口：左「记住我」复选框、右「忘记密码？」文字链接（跳 `/forgot-password`）。**「记住我」默认勾选**，它只决定 token 落 `localStorage` 还是 `sessionStorage`（勾 = 活到 JWT 自然过期，不勾 = 关掉标签页即失效），不改变服务端签发的 token、也不进登录请求体（business-model.md §3.1）。主按钮文案「立即登录」。成功跳转优先级：URL 上的 `redirect` 参数 > 首页；从找回密码页过来时邮箱带回登录框。失败展示后端返回的中文原因，字段级错误标注在对应输入框下。
- **注册**：字段顺序为 **用户名 → 邮箱 → 密码 →（发送验证码）验证码 → 确认密码**。主按钮文案「立即注册」。口令 8–72 位（72 是 BCrypt 的截断边界）、用户名 2–30 位且只允许中文/字母/数字/下划线/中划线、邮箱 ≤255（对齐列宽），这些门槛由后端 `RegisterRequest` 的声明兜住、前端镜像同一份数字（不各写一套），中文原因原样带回。验证码框与「发送验证码」按钮同处一格，按钮发码后进入 `Ns 后重发` 倒计时不可点态。**这五行不许随意重排**——要挪先说清为什么（现序是用户名置顶定身份，验证码紧跟口令之后、确认压尾）。
- **找回密码**（`/forgot-password`，沿用同一顶栏与表单档）：邮箱 →（发送验证码）验证码 → 新密码 → 确认新密码，四格齐备才允许提交。**两步都不泄露邮箱是否已注册**：发码成功的话术是「若该邮箱已注册，验证码将发送至您的邮箱」，未注册也回同样的成功且不投递；重置失败统一报「验证码错误或已过期」，不区分「码错」与「没这个邮箱」（business-model.md §3.2）。成功后一次性提示「密码已重置，请用新密码登录」并跳登录页、把邮箱带过去，同时作废改密前签发的 token（服务端推失效水位）。
- 注册入口常显；开关关闭时（`registration_enabled`，经公开 `GET /site/settings` 下发）由后端拒绝注册，页面展示后端返回的中文原因；前端不自行判断开关状态、也不把注册框改成灰态。
- 已登录访问登录/注册/找回密码路由：直接重定向到首页，不渲染表单。

### 3.6 关于

- **单列**（不是双栏，也没有侧信息列）：身份头 → 导语 → 「本站技术栈」清单 → 页脚。头带是一枚 72px 头像 + 名字 + 那一行身份说明（`about_role`）；导语独立成段，字号就是正文档 `--text-base`、靠 1.85 的行高把它与界面文字隔开——**这一页不做第二档展示字号**。
- **四段文案全部后台可配**：`name` / `role` / `lead` / `avatar`，取自公开 `GET /site/about`，后台在「系统设置 → 关于页文案」里改（`PUT /admin/about-content`），头像走 `/upload/site-image`。**接口返回前先按内置默认文案渲染**，后台清空某项时也由它兜底，所以这一页永不出现空标题或空头像。内置默认值在 `SettingsService`（Java）与 `AboutView`（TS）**各存一份、必须同字**——这是双份交付物的已知代价，改一处就得改另一处。头像为空时回落随发布的 `default-avatar.svg`，不放占位图。
- 「本站技术栈」那一组 `键 → 值` 是**这一页唯一仍是前端静态内容的一段**（分组标题与技能串写死在视图里），不入库、后台改不了；要它可配就是新裁决，别顺手加进 `about_*` 那四键里当一个 KV。
- 无装饰图、无时间线动画、无社交图标矩阵、**不列联系方式**——取不到真值的东西不代写，也不留一个空着等填的字段（P3、P8）。

### 3.7 个人资料 / 账号设置

- **个人资料**（个人主页）：头像上传（圆形预览 + 上传中态）、昵称、**职业**、简介，编辑以弹窗形态出现。头带与行内的名字下面都跟那一行职业，为空就不显示。职业一格是**可选可自填**的：给了几个常用值当下拉快捷入口，但控件必须开 `allow-create`——快捷入口是便利不是数据约束，列表外的值照收；上限 30 字符（对齐列宽）。**清空职业要提交空串而不是缺这个键**：请求体里没有 `occupation` 时后端按「不改这一列」处理，旧值会留着。头像尺寸上限与格式白名单由上传契约决定（魔数裁决、扩展名服务端给，见 business-model.md §5.6），界面只做前端预校验与失败提示。
- **个人主页含四个选项卡：我的文章 / 关注 / 粉丝 / 点赞**（2026-10-02 转正，语义见 business-model.md §3.2）：
  - 我的文章：只列本人的 **已发布 + 已下线** 两态（`offline` 打「已下线」徽标，与草稿箱的状态徽标同一套：6px 圆点 + 文案，功能色只作提示）；**草稿与定时不在这里出现**，它们归「我的草稿」（§3.8），一处一份不重复列。行内给阅读入口，另给一枚**就地上下线开关**（只带 `status` 走部分更新：不动正文、不动首发时刻、抹不掉下架留痕），本页只收 `published` 与 `offline`，所以切换状态不会让那一行离开列表；
  - 关注 / 粉丝：本人的两份名单，行内展示头像/昵称/简介/职业，「我关注的」行内可取关（可撤销操作直接执行 + 一次性提示，不弹确认）；同一套名单在**他人视角**长成作者主页那一页（§3.12），那边的按钮同样是「关注 / 取消关注」，取关只对本人这一侧开放；
  - 点赞：本人点赞过的**已发布**文章，按点赞时刻倒序（文章后来被撤下的就不再出现在这里）；
  - 页头统计行展示关注数与粉丝数，点击切换到对应选项卡。
  - **页内搜索条**（本页与作者主页各一条，同一套结构与判据）：进入搜索态时**整条选项卡换成搜索条**，`<transition>` 常驻、`v-if` 放在子元素上（`v-if` 套在 transition 根上会让返回后整页空白），过渡收尾用 `@after-leave`；头带**让位不撤位**（`visibility` + 绝对覆盖，布局不跳）。输入走 800ms 防抖，但**返回与 `Esc` 退出时必须清词并立刻重拉**——有词就 `flush()` 掉排着的防抖（返回不等那 800ms），没词就 `cancel()` 再自己拉一次（否则「删字删到空」那次排着的防抖会把列表留在筛过的状态）。顶栏那个全站唯一的框搜不到这一页的内容，所以这条框成立（判据：只有顶栏搜不到的语料才配有框）。
- **页头标题为「账号设置」**（2026-10-03 定名，路由 `meta.title` 同值）。入口文案仍是账号下拉与窄屏抽屉里的「设置」，短标签不随之拉长；旧标题「系统设置」与 §3.11 的后台「系统设置」重名，前台不得再用。
- **账号设置页含主题控制**：允许显式指定浅色/深色（见 §6.3）。
- **账号设置页含邮箱修改**：弹窗流程为新邮箱 + 验证码（带 60s 重发倒计时按钮态）+ 当前密码，三项齐备才允许提交；成功后给出「需用新邮箱重新登录」的提示并登出跳转登录页（JWT subject 是邮箱，后果依据 business-model.md §3.3）。
- **资料编辑仅存在于个人资料页（弹窗形态）；账号设置页不得出现头像/昵称/简介表单。**

### 3.8 我的草稿

- 前台框架下的列表页，展示未发布内容（草稿与定时合并展示，语义见 business-model.md A3.1）。
- 行内：标题、更新时间、状态标识（草稿 / 定时，定时项显示计划时刻）、编辑入口、删除。
- 页头提供「清空草稿」。删除与清空**均须二次确认**，确认文案写明对象与数量。
- 定时状态必须**与「已发布」视觉可区**，避免博主误判已上线。

### 3.9 编辑器

- **全屏工作台，三段式**：图标化顶栏（返回 · 保存状态 · 预览 · 大纲 · 打字机模式 · 主按钮）+ 居中画布 + 右侧可折叠**大纲**栏（仅 ≥60rem）；文章设置不在右栏，在主按钮打开的抽屉里，窄屏该抽屉收为底部上拉。
- **画布**：标题是无边框大字号输入；正文区宽度按阅读宽度上限（`--measure-prose`，画布与预览面同宽）；**编辑所见即所得，不展示 Markdown 源码高亮编辑器形态**。**已知差量（2026-10-05）**：详情页阅读列撑满容器轨道后比画布宽 150px，同一篇正文两端**换行位置不同**，插图触到 `--figure-max-h` 的临界也不同。「所见即所得」不含换行位置，**不要为对齐它把详情页再收回去居中**。
- **保存状态必须在顶栏可见**（已保存 / 保存中 / 未保存），是本页唯一的持续反馈位。
- **文章设置只有主按钮一个入口**（顶栏齿轮已于 2026-10-04 撤下，一枚主按钮就够）：抽屉含分类选择（发布必需）、标签、封面上传、发布方式（立即 / 定时：定时需日期 + 时间，且禁选已过时刻）。草稿态主按钮文案是「发布」，抽屉露出发布方式区；已发布态是「更新」，抽屉只留分类 / 标签 / 封面 / 下线，确认文案「保存更新」，载荷不带状态所以不会把已发布打回草稿。
- **既没有摘要输入项，也没有 SEO 设置段**（两项都于 2026-10-03 撤下，原先的「自动生成」按钮与三个带字数提示的输入框一并删除）：摘要由服务端在对外发布时从正文派生，SEO 三元组由服务端按回落链合成，两者都没有作者可填的入口（business-model.md §2.3、§2.10、§4.2 第 6 条）。留着的框就成了「填了也会被无视」的字段，与 P3「最少字段」直接冲突。
- **发布按钮的禁用态由「标题与正文非空，且已选分类」决定**（立即发布与定时发布都要求已选分类）；不满足时禁用而不是点击后报错。定时时刻非法时用一次性提示拦截，不清空用户输入。
- 插图与封面上传：上传中给局部加载态，失败给一次性提示且不静默吞掉错误。
- 禁止：字数统计仪表盘、AI 辅助面板、版本历史列表、协作者头像（业务未定义）。

### 3.10 发布成功

- 独立单列页面：成功标识 + 文章标题 + 「查看文章」主按钮 + 「继续写作」次级入口。
- 不展示阅读量/点赞数等此刻无意义的数字。

### 3.11 后台页面

| 页面 | 构成 | 硬约束 |
|---|---|---|
| 工作台 | 概览指标卡（用户数 / 文章数 / 待审评论数 / 总阅读量）+ 最近文章 + 最近评论 | 指标卡只放接口真值；待审评论数为 0 时仍显示 0（这是真值，与 P8 不冲突）；不画趋势图、不做假 sparkline |
| 文章 | 按状态（含「已下线」）、按作者筛选 + 表格 + 行操作（编辑 / 设置 / 删除）+ 分页 | **四种状态（草稿 / 已发布 / 定时 / 已下线）用文字标签而非纯颜色区分**。**行内「设置」弹窗**是置顶与上下线的唯一编辑面（不必进写作编辑器）：置顶开关 + 排序权重 + 分类 + 上下线四件事，其中**权重只在开关打开时才出现**（不置顶的行没有先后可言），提示语写明「多篇置顶按权重从大到小、同权重按发布时间倒序」，下线那支写明「下线只收回可见性：正文、分类与首发时间都保留」。**下架留痕在行上可读**：仅当该行当前是 `offline` 时显示「由 {操作者} 于 {时刻} 下线」，`offlinedAt` / `offlinedByName` 都必须先进列表那条查询（弹窗复用列表行，凡是要在弹窗里显示的值都不能只待在详情里），公开详情响应里没有这两列。原先的「待补全 SEO」开关与「SEO」列已于 2026-10-03 随手动 SEO 链路一并删除（business-model.md §2.10）：摘要改为服务端派生后，「哪篇还没填」这张清单没有人能行动，留着就是 P3 禁止的「以后可能用到」的筛选器 |
| 评论 | **一级页签两个：「评论审核」与「违禁词库」**。评论审核 = 待审核 / 已通过 / 已拒绝 三个状态页签 + 通过 / 拒绝（仅待审核页签可用）/ 删除 + 表格「命中词」列；违禁词库 = 单条添加（词 + 动作下拉）+ 批量导入弹窗 + 表格（词 / 动作 / 状态 / 添加时间 / 启停 · 删除）+ 关键词搜索 + 分页 | 两级页签分工固定：**一级切管理对象**（评论 / 词库），**二级切筛选**（状态），不得把状态提到一级。待审队列清空后必须有空态文案；裁决操作有加载态；删除须二次确认，文案写明连带删除的回复数。「命中词」列取 `hit_word`，为空显示 `—`（关审核、未命中、该列上线前的存量评论三者不必区分，db-design.md §5.6）；它是解释性展示，**不可点、不做按词反查**（business-model.md §6）。词库的动作与状态用文字标签而非纯颜色区分；「停用」文案不得写成「删除」；批量导入弹窗须写明拆分规则（换行与中英文逗号均可）并在提交后回显 `added / skipped` 两个数；重复词按后端返回原因就地提示 |
| 分类 | 列表 + 新增 / 重命名 / 删除 | 「文章数」列是**含草稿与定时的全量口径**（business-model.md §4.6 第 1 条）；该数大于 0 时删除入口给的是**阻断提示**而非二次确认——文案写明篇数与「删除分类前需先迁移这些文章」，确认后没有删除动作（**不得再写「删除后显示为未分类」**，后端本就不删有文章的分类）；空分类才进入二次确认；重名按后端返回原因就地提示 |
| 标签 | 列表 + 新增 / 重命名 / 删除 / 合并 | 与分类页同一套表格与操作结构，不另做交互范式；合并需选择源标签与目标标签并二次确认，文案写明将被改写的文章数 |
| 用户 | 列表 + 启用 / 禁用 | 禁用是状态变更不是删除，文案不得写「删除用户」；操作前二次确认 |
| 日志管理 | **一级页签两个：「访问日志」与「登录日志」**，页签由路由驱动（`/admin/logs/visits`、`/admin/logs/login`），侧栏只有这一个入口。访问日志 = 时间范围 + 概览四卡 + 趋势柱 + 三个 Top 榜 + 明细；登录日志 = 锁定策略卡 + 概览三卡 + 攻击 Top 榜 + 明细（时间 / 邮箱 / 来源地址前缀 / 结果四个筛选可任意组合） | 页签只导航、不持有状态，数据由路由上那个视图自己取；**不引图表库**，趋势柱与次数条都是按窗口内最大值归一化撑出来的 div；来源地址列一律显示脱敏串（`112.10.*.*`），响应里没有原始地址（db-design.md §2.9、§2.13）；UA 只出七类粗标签、原文进悬浮提示；结果与状态用文字标签而非纯颜色区分；地址前缀筛选框的占位文案要写明「可粘屏幕上那串」；策略卡的说明必须含合法范围与「改动只影响之后新开的计数窗口」，越界值由后端回 400 就地提示，**前端不做静默夹紧**；两张 Top 榜的聚合键不同（访问按脱敏合并后截断，登录按「邮箱 + 原始地址」对不合并），这是两块场景的差别，不得为了「看着一致」改成一套 |
| 系统设置 | **四块，不是一屏开关**：运行开关（评论审核 · 开放注册）→ 评论防护（字数上限 · 发布间隔）→ 站点信息（站点名称 ≤30 · ICP 备案号 ≤50 · 站点域名 ≤255）→ 关于页文案（名字 · 身份 · 导语 · 头像） | 前两块是**点控件**，沿用「标签占左缘、控件贴右缘」那一行结构；后两块是**块控件**，标签在控件上方——同页两套排布按控件类型分，不按审美分。开关文案写明后果，且措辞须与两层审核一致（开 = 新评论先经违禁词机审，命中 `pending` 词才进待审、命中 `reject` 词直接拒绝）；**违禁词不在本页**——词库已于 2026-10-03 移到「评论管理」，本页审核开关的描述须指向那里，且**不得留第二个录入入口**（business-model.md §2.6、§2.9）。两个评论防护项都要写出「0 表示不限制」，合法区间（0–5000 / 0–86400）由接口随响应下发、**前端不抄第二份数字**，越界值后端回 400 就地提示、**不做静默夹紧**（读侧才夹紧，§3.11 日志管理那条同一套不对称）。「站点域名」留空时按当次请求 Host 兜底，所以这一格的说明必须写「正式上线必须填」（README 与 business-model.md §2.10）；「ICP 备案号」为空时页脚那一行整个不渲染，不留空行。保存动作是显式按钮，不做切换即静默保存 |

- 后台表格通用约束：行高一致；操作列右对齐且用文本按钮或统一图标；空态一行文案居中；加载态用表格遮罩而非页面跳动；分页固定在底部。
- 后台的删除 / 禁用 / 拒绝类操作，必须二次确认（见 §5.4）。

### 3.12 作者主页（他人视角，`/authors/:id`）

> 本节挂在 §3.11 之后是**编号妥协**：`/users/*` 那套锚点被三份文档交叉引用，插到 §3.7 之后要把后面所有小节挪号，得不偿失。它是**前台框架下的页面**，沿用站点顶栏与容器。语义（四个 tab 全做、公开无开关）见 business-model.md §3.2「作者主页」与 §4.7。

- **身份卡只读**：结构和个人主页那一头同一份，但**编辑入口只在 `/profile`**——看别人的页面不给改的东西。76px 头像 + 名字 + 职业行 + 简介行，后两行**为空就整行不写**，不放「暂无」「未填写」这类占位（P8）。
- **关注按钮在卡右上角**（`!isSelf` 时才有）：文案在「关注」与「取消关注」之间切换，与详情页作者卡同一套说动作的词；已关注态同样只由洗染底 + 描边区分。状态与数字都以接口返回为唯一来源，禁止乐观更新，提交中 loading 并禁用重复点击。
- **三格统计与详情页作者卡同口径同顺序**：文章 / 粉丝 / 阅读，全部取「该作者全部已发布文章」的聚合，取不到显示 `—`。
- **四栏**：TA 的文章 / 关注中 / 粉丝 / 点赞。行式与个人页一致（同一套列表行，§3.1）。「关注中」「粉丝」两栏行内带关注按钮——**这是站内唯一的就地回关入口**，不必先点进对方主页；`followed` 与 `followsMe` 同时为真时那一格写「互相关注」（只是文案，不是新语义，见 business-model.md §5.7 第 12 条）。「点赞」栏只列该作者**已发布**的文章。
- **栏内搜索只对「TA 的文章」这一栏**：搜索条结构与个人页同一条（§3.7 页内搜索条那条），占位文案必须写「输入标题或正文关键词…」——顶栏的框本来就搜得到标题，这一栏的框要给的是「在这个人的语料里搜」，只写「搜索」会让人以为它和顶栏是一回事。
- 名单行一律只出头像 / 昵称 / 简介 / 职业（`UserBriefVO` 的五列，另带 `followed` / `followsMe` 两枚只表示**浏览者与这一行的关系**的布尔），**没有邮箱、角色、状态**；页面对匿名可访问，未登录时两枚关系位是 `null`（不是 `false`），点关注按 §5.5 引导登录。
- **两种「读不到」必须分开报**：作者不存在、已注销、或**已被禁用**（三种情况接口都是同一个 404，不给差异反馈，见 business-model.md §2.2）→ 「这位作者不存在。TA 可能已注销，或链接有误。」+ 返回首页；服务没答上话（5xx / 网络失败）→ 「加载失败。」+ 重试按钮，话术里要写明「这位作者可能还在」——**把服务故障报成人已消失**是一条不可原谅的错。这一页与详情页那一处「不存在或无权访问」的合并口径不同，那是因为详情页要防存在性泄露，这里没有那个理由（作者主页本就公开）。

## 4. 视觉规范

> 一切值都必须引用 Token 名。下表写的是**语义归属**，不是数值来源。

### 4.1 颜色

| Token | 语义 | 必须用于 | 禁止用于 |
|---|---|---|---|
| `--color-paper` | 页面底 | 最外层背景 | 卡片 |
| `--color-paper-2` | 抬升面 | 卡片、输入框、抽屉、下拉面板、表格行 | 大面积背景铺满 |
| `--color-paper-3` | 凹陷/反馈面 | 代码块、引用块、hover 底、选中行 | 正文文字底色 |
| `--color-ink` | 墨·主级 | 标题、强调正文、图标 | 辅助信息 |
| `--color-ink-2` | 墨·次级 | 正文、摘要 | 标题 |
| `--color-ink-3` | 墨·辅助 | 日期、计数、说明文字 | 交互主文案 |
| `--color-ink-4` | 墨·最弱 | 占位符、禁用文字 | 可读正文 |
| `--color-rule` | 发丝线 | 分隔线、卡片描边、表格线 | 交互控件描边 |
| `--color-rule-strong` | 控件描边 | 输入框、按钮等非交互态描边（对比度需可辨） | 版面分隔 |
| `--color-accent` | 朱砂·唯一强调 | 主按钮、选中态、正文链接、hover 点睛、置顶与排名 | 大面积底色、标题字色、装饰色块 |
| `--color-accent-ink` | 朱砂加深 | accent 元素的 hover / active | 独立第四种强调 |
| `--color-accent-wash` | 朱砂洗染 | 选中项底色（筛选激活、菜单当前项） | 非选中项 |
| `--color-focus` | 焦点环 | `:focus-visible` | 装饰描边 |
| `--color-danger` / `--color-success` / `--color-warning` | 功能色 | 校验失败、提交成功、待处理提示、未保存点 | 版面配色、图表配色 |
| `--color-overlay` | 遮罩 | 弹窗、抽屉、上传蒙层 | 卡片底 |
| `--color-stage` / `--color-stage-ink` | 灯箱台面·**暗面不随主题反转** | 正文图片灯箱那一层的底与其上的控件文字（全站唯一一枚暗面，开灯箱时页面本身被它盖住） | 版面区块底、正文文字、任何非灯箱场景 |
| `--color-qr-surface` / `--color-qr-ink` | 扫码面·**主题不变量** | 分享二维码的底与模块 | 任何版面元素 |

- 暗色只改 `html.dark` 的 Token 块（纸降、墨升、朱砂提亮降饱和），**组件不写暗色特例**。
- **两处主题不变量例外**，都在 `:root` 声明、`html.dark` 刻意不覆盖：① `--color-qr-surface` / `--color-qr-ink`——反色二维码扫码器读不出；② `--color-stage` / `--color-stage-ink`——看图必须压在暗面上，否则暗色主题下浅面配浅图、深控件配深面，两头都读不出。两枚都是功能件不是配色，加第三枚不变量要先在这里登记理由。
- 明暗两套共用同一色相体系；禁止出现纯黑 `#000` 与纯白 `#fff`。
- 文字与底色对比：正文级 ≥4.5:1，发丝线与非文字图形 ≥3:1。Agent 改 Token 值后必须重算，不能只看观感。

### 4.2 字体

| Token | 用途 |
|---|---|
| `--font-display` | 标题；与正文同族，靠字重拉开层级 |
| `--font-body` | 正文与界面文字 |
| `--font-mono` | **仅数据场景**：站标、日期、计数、排名、行内代码 |

- 字阶（1.25 大三度）：`--text-xs` / `--text-sm` / `--text-base` / `--text-md` / `--text-lg` / `--text-xl` / `--text-2xl`——**七档，七档都有消费者**。**禁止跳出自定义字阶取中间值**。
- **文章标题那一行走 `--text-2xl` + 字重 700**（窄屏退到 `--text-lg`，编辑器画布的标题输入是另一档 `--text-lg` + 500，两处的分工见 §3.9 与 business-model.md 的排版裁决）。原先另有第八档 `--text-display`（`clamp()` 随视口），**全仓零引用，2026-10-05 已删**：一枚没有落点的档留在字阶里，下一个读文档的人会当它是「超大标题的既定规格」直接引用，把一个从未验证的视觉决策变成事实。将来真要用随视口缩放的大标题，先在本节写清它落在哪个元素、上下限各多少，再补声明。
- 中文正文字号下限 12px；后台表格最低 12px、正文页主正文不小于 `--text-base`。
- 标题一律正体，**禁止斜体标题**。
- 所有数字（计数、日期、篇数、排名）必须挂等宽数字工具类，禁止比例字。
- 字体自托管，禁止外链 Google Fonts；代码高亮全站统一一套 One Dark（阅读页与编辑器预览同一套，不随主题切换而换）。

### 4.3 圆角

- `--radius-xs`（2px 级）：内联小元素、代码行内块
- `--radius-sm`：输入框、按钮、缩略图、标签、工具栏按钮
- `--radius-md`：面板、卡片、弹层
- `--radius-lg`：弹窗、抽屉等最大面积浮层
- 圆角整体偏小。**禁止**胶囊化大圆角、圆形卡片、`9999px` 这类任意值。**例外清点到此为止，共三枚**：① 头像（非容器）与文章页悬浮操作栏的圆形图标按钮；② 计数角标；③ **悬浮操作栏那枚关注药丸**——它骑在 44px 头像的下缘，圆角必须跟着头像那条弧收，收成 `--radius-sm` 会变成一块贴在圆上的方片；它是**状态芯片不是按钮档**（高 1.25rem、实底、只一枚描边环），不给站内其他控件援引。**这一条例外把形状与字面值一起登记**：那枚药丸的 `border-radius: 999px` 写在组件里，是 §6.1「禁止裸圆角」在站内的**唯一一处让位**。不为此补一枚 `--radius-pill`：只有一处使用的字面值一旦升成档位，四档圆角就多了半个谁都能用的档。**触发条件写在这里**——站内出现第二枚胶囊时，才补 Token 并把这一条改回常规登记。在那之前，新控件的圆角一律走 `--radius-xs` / `-sm` / `-md` / `-lg`，援引这枚药丸的写法就是违规。

### 4.4 阴影与分层

- 全站唯一阴影：`--shadow-whisper`，只用于抬升面（卡片、下拉、弹窗）的极轻离地感。
- 层级优先用发丝线 + 底色微差表达。**禁止**多层阴影叠加、彩色阴影、长投影、玻璃拟态（含背景模糊）。
- z 轴档位固定八档 `--z-base`(1) → `--z-raised`(10) → `--z-dropdown`(100) → `--z-sticky`(200) → `--z-modal`(400) → `--z-toast`(500) → `--z-tooltip`(600) → `--z-lightbox`(700)；**禁止**写裸数字。灯箱压在提示与提示条之上是刻意的——看图时任何浮层都不该盖住它；`--z-lightbox` 是第八档而不是新档系，档位之间不许插值。

### 4.5 间距

- 4pt 刻度体系：`--space-3xs` → `--space-2xs` → `--space-xs` → `--space-sm` → `--space-md` → `--space-lg` → `--space-xl` → `--space-2xl` → `--space-3xl`。**禁止任意值。**
- 语义归属（新增区块先套这四条，再考虑别的档位）：
  - 页面级区块之间 → `--space-xl`
  - 列表行纵向节奏 → `--space-lg`
  - 组件内部（图标与文字、标签间距） → `--space-xs` / `--space-sm`
  - 表单字段与输入框内边距 → `--space-md`
- 版面常量：内容容器最大宽度 `--container-max`；顶栏高度 `--header-h`；正文阅读列宽度上限按现有阅读列约定，不得随视口无限加宽。

### 4.6 图标

- **版面图标只有一套**：站点自绘内联线性图标，统一描边宽度 1.5、继承currentColor、16px 基准；可交互图标必须带无障碍名称，**图形定不死它在干什么的还要带悬浮提示**（判据与规格见 §5.2，原先的「名称或提示二选一」已于 2026-10-04 收紧，二选一让提示成了可选项，正是顶栏那几枚没人看得懂的原因）。**后台管理界面与上传控件允许使用 Element Plus 官方图标包 `@element-plus/icons-vue`**（仅限 `AdminLayout` 导航、上传按钮这类功能性小图标，前台阅读面仍用自绘）。
- Element Plus 组件**内部自带**的图标（选择器箭头、日期、上传、表格排序）保留原样，不计入第二套体系。
- **品牌单色标是仅有的例外**：指向外部平台的动作（分享菜单的微博 / 微信）允许内联该平台的单色官方形——path 数据取自 Simple Icons（CC0），落在 `src/assets/icons/share-marks.ts`，`fill` 继承 `currentColor` 跟随文字色，尺寸仍按 16px 基准。它**只用于指向该品牌的动作**，不得挪作站内导航或装饰，否则就是第三套图标体系。
- **禁止**引入第三套图标库、emoji 当图标、图标 + 插画混用。
- 小字形（圆点、wordmark 描边）允许按视觉重量微调描边宽度，但新图标一律先按 1.5 写。

### 4.7 动效

- 时长三档：`--dur-micro`（微交互）/ `--dur-short`（常规）/ `--dur-long`（大位移）。缓动：进入用 `--ease-out`，离开用 `--ease-in`，往复用 `--ease-in-out`。
- **允许存在的动效只有四类**：路由切换的透明度淡入（只淡不移位）、回顶按钮显隐、列表换页淡入、导航进度指示。新增动效必须说明它反馈了什么动作，否则不写。
- 浮层（抽屉 / 弹窗 / 下拉）与折叠块的开合沿用组件库默认过渡，属操作反馈，不受「只有四类」限制；不得自绘位移动画。
- **导航进度指示**：页面顶边一条 2px 的强调色细条，反馈的是「这次导航的请求还没回来」，覆盖懒加载路由的 chunk 下载等待；导航落地或失败即收，不常驻。它由 `nprogress` 承载，但库自带的转圈与右端旋转光晕不渲染（那是默认装饰，与发丝线语言无关），颜色取 `--color-accent`。细条的推进只作用于自身宽度，不构成下条禁止的内容位移。
- **禁止**：渐变、玻璃拟态、Bento 网格、大卡片堆砌、位移动画、入场逐项错峰动画、循环呼吸/闪烁动效、数字滚动计数动画。
- `prefers-reduced-motion: reduce` 由全局统一降级（缩短时长、关闭平滑滚动），新组件不必各写兜底。

## 5. 交互要求

### 5.1 反馈

- **失败必须出声**：请求失败统一提示后端返回的中文原因，**前端不二次拼装文案**；同一动作有多个字段错误时，字段级错误标注在输入框下方，另有且仅有一条一次性全局提示。
- **成功反馈分级（现状口径，不得自行扩展）**：编辑器的周期性自动保存静默；手动保存给一次性提示；发布成功走独立页面；其余操作类动作给一次性提示。禁止为同一动作同时给 toast + 页面跳转 + 内联文案。
- 一次性提示同一时刻只保留最新一条；提示不打断输入、不遮挡表单提交按钮。
- 加载中：区域级操作用按钮 loading；页面级用区域占位（不得用闪烁的空白页）；禁止整页锁死输入。跨页导航的等待由顶部进度条承担（见 §4.7），它只表示「导航还没落地」，目标页自身取数期间的占位照旧要写。

### 5.2 悬停 / 按压 / 焦点

- 悬停 = **颜色变化**（链接与自绘按钮：主墨 → 朱砂）。必要时允许 1px 按压位移。**禁止**「变色 + 阴影 + 位移 + 缩放」多信号叠加。
- **悬浮提示的判据**：光看图形定不死它在干什么的纯图标按钮必须有（打字机模式、大纲、主题切换），图形唯一可读的不加（返回箭头、关闭 ×）。气泡由站点自绘：主墨底 + 反色文字 + 指向箭头，`z-index` 取 `--z-tooltip`，**文案直接取按钮的 `aria-label`**，不另立第二份词表；吸顶层（编辑器顶栏与其下工具栏）一律在按钮**下方**弹出，向上会被顶栏切掉。**带可见文字的控件不给气泡**——文字本身就是说明。触屏没有 hover，所以提示不得作为唯一的说明渠道，`aria-label` 与旁边的状态文字必须自己说得清。已落地：编辑器顶栏（2026-10-04）；详情页悬浮栏的分享 / 点赞 / 评论与主站顶栏的主题切换按此判据待补。
- Element Plus 组件的悬停/激活语义：文字转主墨、底转 `--color-paper-3`；选中态统一朱砂洗染底 + 朱砂文字。与自绘控件的语义不混用。
- 焦点环必须**立即出现、永不做动画**：2px 实心描边 + 外偏移，禁止 `outline: none` 而无替代方案。**全仓 7 处 `outline: none` 清点完毕，登记的替代方案共四类**，新控件要免掉默认焦环，必须先在这里加一类同类说明，不许默默 `outline: none`：
  - **三处搜索框**（顶栏 §2.1、个人主页、作者主页）：`outline: none` + 描边转 `--color-rule-strong`，顶栏那一处同时把框体拉宽；宽度过渡只作用在 `width` 上，焦环本身不动画。
  - **Element Plus 的内层真实输入**（`.el-input__inner`、`.el-textarea__inner`、`.el-select__input`）：`outline: none` 写在 `global.css`，聚焦态由**外层 wrapper 的边框**表达——不这样写多选标签这类控件会顶出双重边框。组件库自己的结构不算第二套焦点语言，因为可见信号仍是一枚描边。
  - **弹层里的自绘输入**（插入链接、图片上传两处）：常态就带 `--color-rule-strong` 描边，`outline: none` 后靠该描边自身承担焦点态。
  - **编辑器标题输入框**（第四类）：画布是无边框书写面（§3.9），补描边会把这块面切成一格一格，所以 2026-10-05 起用**整行底色微差**表达——`&:focus-visible { background-color: var(--color-paper-3) }`，取的就是「凹陷/反馈面」那一档，与 §5.2 悬停「颜色变化」同一种语言。**不加过渡**：焦点信号必须立即出现（本条第一句）；也不加 `:focus` 之外的变体，`focus-visible` 保证鼠标点进去不染色、只有键盘停上来才亮。
- 纯展示件（统计数字、文章正文、发丝线分隔）不加悬停玩法。可交互面收敛为：导航、筛选、搜索、主题切换、回顶、表格行操作。

### 5.3 表单

- 必填项用星号标记，不用「（必填）」长文案；同一表单内标签位置一致。
- 校验时机：失焦后校验单字段，提交时校验全表单；提交按钮不在非法态下静默成功。
- 提交后按钮进入 loading 并禁用重复点击，直至响应返回（点赞类幂等动作的语义见 business-model.md §4.5）。
- 验证码类按钮在发送成功后进入 60s 倒计时不可点态；倒计时期间允许修改输入框内容。
- 破坏性输入（清空筛选、放弃草稿）需可预期：不做「一键清空无提示」。

### 5.4 确认与危险操作

- 删除文章、删除分类/标签、合并标签、删除草稿 / 清空草稿、禁用用户、拒绝评论、删除评论：**必须二次确认**，确认文案写明对象与被影响数量。例外：分类下仍有文章时删除本就不可执行，此时给阻断提示而不是确认框（见 §3.11）。
- 确认弹窗中主按钮用危险色语义，且文案是动词（「删除」），不是「确定」。
- 可撤销的操作（如改状态）优先直接执行 + 结果提示，不滥用确认。

### 5.5 登录引导

- 未登录触发需要身份的动作（点赞、评论）：先一次性提示说明需登录，再跳登录页并携带 redirect 回跳参数；回跳后**不重复弹出提示**。
- 登录态失效（token 过期、账号被禁用）：由请求拦截器集中处理，清掉本地 token、提示取后端返回的中文 message（不自造文案），并跳登录页；后台路由同样回登录页，不得渲染空白后台；同一次失效只出一条提示（business-model.md §5.3 第 4 条）。

### 5.6 路由与滚动

- 路由切换的滚动位置由布局层统一处理（过渡结束后再消费目标位置，避免闪屏）；**新页面不得绕过该机制自行滚动**。
- 从文章页返回列表必须恢复原滚动位置与已加载页码（由布局层保持列表页状态，见 §2.1 编辑器例外）。
- 页内锚点（目录跳转）平滑滚动；正文内标题可锚点定位。
- 长文页必须提供回顶入口，仅在向下滚动一定距离后出现。

### 5.7 无障碍

- 图标按钮必须有无障碍名称；筛选/开关必须有可读状态（`aria-pressed` / `aria-current`）。
- 状态、错误、结果不得只靠颜色传达，必须带文字（草稿 vs 定时 vs 已发布用标签）。
- 键盘可完成：顶栏导航、筛选、搜索、弹窗关闭（Esc）、表格行操作。
- 弹窗打开时焦点进入弹层、关闭后回到触发元素。
- 表单控件必须有可见标签，禁止只用 placeholder 当标签（placeholder 在输入后消失，不满足说明作用）。

## 6. 技术实现约束

### 6.1 CSS 方案

- **单一 Token 真源**：`cloudlog_web/src/assets/styles/variables.css`（`:root` 浅色 + `html.dark` 深色 + 两段 Element Plus 变量映射）。
- **样式分层按序生效**：`reset.css`（归零）→ `variables.css`（Token）→ `global.css`（全局元素与工具类）。后台专用样式只由后台布局引入，作用域限后台，**不得当作全局层**。
- **硬性约束：组件内禁止出现裸色值、裸字号、裸间距、裸圆角、裸阴影、裸 z-index、裸时长**，一律引用 Token。
- **不设第二份 Token 交付物**：不新增 `tokens.css`、不引入 Tailwind `@theme`、不引入 DTCG/shadcn 导出。将来若换工具链，按 Token 名一一映射，不并行维护。
- 组件样式使用组件作用域书写，不新建全局覆盖层；**禁止在组件里散写 `--el-*` 覆盖**（Element Plus 的接管只走 variables.css 的两段映射）。
- 覆盖第三方编辑器样式时允许沿用现有强制覆盖写法，但仅限第三方作用域，且颜色必须引用本站 Token。
- **禁止新增 UI 依赖库、状态管理库、图标包、动画库**（口径同 business-model.md C4）。

### 6.2 组件风格

- 组件库固定为现有 Element Plus；能用现有组件就不自绘。
- 主按钮（强调色填充）**只用于提交类动作**（登录、注册、发布、保存、确认）；次级入口用发丝线描边按钮；最弱用纯文本链接。一个界面内主按钮不超过一个。
- 卡片范式固定：抬升面底 + 发丝线描边 + 一枚极轻阴影；hover 反馈只转强调色或凹陷底。
- 表单、表格、弹窗、抽屉、下拉均沿用组件库默认结构，仅通过 Token 映射换肤，**不重写组件内部 DOM 结构**。
- 文案：动词开头、中文界面词全站统一（「登录 / 注册」「清除筛选」「换一换」）；同一概念不得出现两种叫法。

### 6.3 暗黑模式实现方式

- 机制：`html` 元素上的 `dark` 类驱动 Token 块切换；由主题 composable 单例管理状态。
- 默认**跟随系统** `prefers-color-scheme`；用户手动切换后写入本地存储固定偏好，此后不再随系统变化。
- **首帧前必须有一段内联脚本**读取本地存储并给 `<html>` 打 `dark` 标——删掉它会导致刷新时闪白。这段属于功能件，改 `index.html` 时不得当作样板代码清理。
- 需要第三方样式联动的（编辑器工具栏图标色等），在组件里把本站 Token 赋给第三方变量，**不引入第二色板**。
- 新增界面时必须同时验证明暗两态的对比度（§4.1）；只允许通过改 Token 值修暗色，禁止写 `.dark .xxx { }` 组件特例（第三方样式除外，且需注明原因）。

### 6.4 响应式实现

- 断点用 `rem`，现有档位（2026-10-05 按代码清点，此前漏记两档）：`34rem`（列表行窄屏：整组标签收起、缩略图降档）、`37.5rem`（顶栏账号簇让位给搜索框）、`40rem`（窄屏/手机）、`60rem`（多栏成立：右栏 + 文章页悬浮竖栏，竖栏窄到汉堡出现才换成文末一行）、`75rem`（三栏加宽）、`84rem`（后台内容区宽度上限）。新增断点必须说明理由并同步这一行，不随意加档。
- 布局优先用流式与网格（`minmax(0,1fr)` 类约束），禁止为宽度写死像素列宽。
- 需要 JS 判断宽度的场景，媒体查询与运行时判断必须**成对使用同一数值**，禁止 CSS 与 JS 各写一套阈值。
- 同一份数据只渲染一处：不允许为宽窄屏准备两份 DOM 靠显示隐藏切换。
- **`max-width` 一侧写补集要用 `-1/16`**：`60rem` 档的窄屏面孔写作 `@media (max-width: 59.9375rem)`（现三处这么写：`ArticleHeader.vue`、`ArticleDetail.vue` 两处）。整档同写（`max-width: 60rem`）会让两档在同一像素上同时命中，窄屏规则被宽屏规则盖掉或反过来；`rem` 下 1px = `1/16rem`，这不是新档位，是同一档的另一半。JS 那侧仍只用 `matchMedia('(min-width: 60rem)')` 这一个数——**成对同值**的规矩见上一条，CSS 的 `59.9375` 是它补集写法的那一半，不是第三个数。

### 6.5 数据展示的落地约束

- 时间展示统一经前端日期库格式化，界面格式与全站一致；「发布于」一类字段为空时显示 `—`，不显示 `Invalid Date` 或 1970。
- 分页组件参数与接口分页字段对应关系见 business-model.md B2.2；UI 只负责展示 `total` 与当前页，不做前端假分页。
- 图片地址统一经现有的地址规整函数处理后使用，禁止在组件里手工拼接存储域名（换域名后果见 business-model.md B1.4）。
- 计数类展示（点赞/评论/阅读）直接渲染接口值，不做前端估算、不做「1.2k」这类未经定义的缩写；缩写规则若要引入必须先补进本文。

### 6.6 禁止事项汇总（Agent 自检清单）

1. 组件内任何裸值（颜色/字号/间距/圆角/阴影/z-index/时长）。
2. 第二套配色、第二套图标体系、第二份 Token 文件、新 UI 依赖。
3. 为暗色模式单写组件样式（只允许改 Token）。
4. 渐变、玻璃拟态、Bento、大卡片堆砌、位移动画、入场错峰动画。
5. 业务未定义的界面元素（推荐位、归档、趋势图、AI 面板、多语切换、消息中心）。分享入口已按 2026-10-02 裁决转正（§3.2，微博 / 微信 / 复制链接，微信二维码前端本地生成、不外呼第三方）。
6. 乐观更新的点赞/计数；估算或装饰性统计数字。
7. 静默失败的请求；把后端中文 `message` 替换成前端自造文案。
8. `outline: none` 无替代；状态仅用颜色传达；placeholder 当标签。
9. 修改 Token 后不同步本文（Token 与语义必须一起改，见下条）。
